# VITAS — עיצוב טאב Facebook

שלב את העיצוב בטאב Facebook הקיים, בפיילוט הנדל״ן HI PARK. זהו עיצוב של המבנה הקיים: כרטיסים, משפך, קמפיינים, פילוח מגדר, פילוח גיל ומודעות מובילות. אין לשנות חישובים, שיוך או הרשאות בעקבות הסקיצה.

## קבצים
- reference/facebook-style-only.png — סקיצה חזותית בלבד. המספרים, יחסי התמונות והטקסט בה אינם מפרט מדויק.
- components/FacebookView.jsx — default export של תצוגת הטאב.
- components/VitasPresentation.jsx + styles/vitas-visual.css — בסיס משותף מהחבילות הקודמות. אם כבר שולב במאגר, השתמש בגרסה המשולבת והתאם imports; אל תדרוס התאמות קודמות. אין להשתמש כאן ב-OverviewPresentation, שמוסיף main ותוכן Google.
- styles/facebook.css — שכבת עיצוב מקומית ב-prefix vfb.
- DATA-CONTRACT.md, ACCEPTANCE.md, VALIDATION.md — חיבור נתונים ובדיקות.

## עבודה במאגר
1. קרא AGENTS.md והנחיות קיימות. בדוק git status ושמור שינויים קיימים.
2. קרא app/admin/page.js, את טאב Facebook ואת כל ה-adapters שלו. תעד מקורות, חישובים, מסננים, טווחי תאריך, הרשאות ופעולות קיימות. שמור baseline וצילום לפרויקט ותקופה קבועים.
3. React 18, Next.js 14 App Router, Heebo, RTL, lucide-react, CSS classes עם משתנים קיימים. אין Tailwind, ספריית UI חדשה או inline styles. אין override גלובלי ל-:root.
4. שמור את המעטפת המקורית: Header, Sidebar, TitleBar, תאריכים, תקציב וטאבים. Facebook אינו כולל תתי־טאבי CRM. הרכיב נכנס ל-main הקיים; אין להוסיף מעטפת או route.
5. טען CSS פעם אחת בסדר globals.css, vitas-visual.css, facebook.css. שלב adapter תצוגה נפרד; אין שינוי reports/source/month או business logic.
6. תחום ל-HI PARK/פיילוט נדל״ן לפי דפוס הפרויקט. שמור isClientView ומבני KLOSS/BCure. אין שינוי Google או טאבים אחרים כתופעת לוואי של CSS.
7. חבר פעולות מיון ופתיחת קמפיין להתנהגות המקורית. שמור כל עמודה ופעולה קיימת גם אם אינה בתמונה.
8. בדוק מול baseline, הרץ Build ובדיקות המאגר, הצג preview למשתמש לפני פרסום.

## מה מחייב במפרט
- עשרת הכרטיסים בסקיצה שווים בחשיבותם החזותית; בשילוב שמור את המדדים האמיתיים. מספר הכרטיסים דינמי ואינו הרשאה להמציא מדד חסר.
- כרטיסים: פעילות בתקופה, לרבות פעילות מלידים ישנים בהתאם להגדרה הקיימת.
- משפך: התקדמות הלידים שנכנסו בתקופה. חשיפות ואז קליקים מוצגים מעליו כאגרגציה של הפרסום, בנפרד מהקוהורט. אין להציגם כמסלול אישי שניתן לעקוב אחריו.
- אחוזים אינם מחויבים בסקיצה. שמור אחוזים קיימים רק עם מכנה מפורש ואוכלוסייה תואמת. אל תסיק יחס מקרי בין כרטיסים למשפך.
- פילוח מגדר ופילוח גיל בטבלאות נפרדות ברוחב מלא, אחת מתחת לשנייה. לא לצופף אותן זו לצד זו.
- מודעות בשתי עמודות בדסקטופ. תמונות 1:1 או 16:9 מוצגות במלואן באמצעות object-fit:contain בתוך אזור מדיה באותו גובה. אין crop/stretch או חיתוך טקסט. קבע ratio ממטא־דאטה של הנכס המקורי, לא מהסקיצה. אם הנכס אינו ביחס מוכר, שמור יחס מקורי ואל תעוות אותו.
- סוגי תמונות/וידאו/קרוסלה נשמרים לפי המימוש הקיים; התמונה בסקיצה אינה סיבה להחליף אותם בסטילס מומצא. אם יש renderer קיים עשיר יותר, שמור אותו עם מעטפת העיצוב.

## אי־דיוקים בסקיצה שיש לתקן בשילוב
יחסי הקריאייטיב בתמונה אינם מדויקים לחלוטין; CSS והנכס המקורי הם הקובעים. כותרות ועמודות בטבלאות בתמונה הן דוגמה מצומצמת: אין להסיר CTR, CPM, עלות לקליק או מדד אמיתי אחר משום שלא הופיע בסקיצה. המספרים והסיכומים המדגימים אינם נתוני אמת.

סרגל התקציב במעטפת עשוי להיות תקציב הפרויקט כולו. אל תהפוך אותו לתקציב Facebook לפי התמונה. שמור את הגדרתו ותן תווית היקף ברורה במידת הצורך. ברפרנס מופיע גם תוכן ניווט מצויר; יש להשתמש ברכיבים ובנכסים המקוריים בלבד.
