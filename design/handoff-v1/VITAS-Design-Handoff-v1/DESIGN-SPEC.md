# מפרט חזותי — המבנה הקיים

## כללים
Heebo בלבד מהטעינה הקיימת, RTL, מצב בהיר. lucide-react במשקל 1.7–2, לא emoji. מקור המיתוג הוא מאגר הפרויקט. הסקיצה היא mood/layout reference; הנכסים והנתונים בה אינם נכסי production.

## שיוך צבעים קבוע
| מדד | tone |
|---|---|
| הוצאה בפועל / תקציב שנוצל | indigo |
| לידים | emerald |
| עלות לליד | violet |
| פגישות שתואמו | sky |
| פגישות שבוצעו | terra |
| פגישות עתידיות | sky |
| פגישות שבוטלו | amber |
| לידים שלא טופלו | indigo |
| הרשמות | emerald |
| חוזים | rose |

ה-CSS משתמש ב--indigo, --emerald, --rose, --amber, --violet, --sky, --terra ובמשתני המשטחים/רדיוסים/צללים הקיימים. הוא מגדיר גרדיאנטים מקומיים --vr-fill המותאמים לטקסט לבן; amber משתמש בטקסט כהה. ערכי --g-* המדויקים לא נמסרו, ולכן אין בחבילה הפניה לשמות מומצאים שלהם. קלוד יכול למפות אותם לאחר בדיקת הקוד והניגודיות.

אין !important עבור עקיפת inline styles (מלבד כלל reduced-motion). אין שינוי גורף ל-root או body. הקוד מיועד לשילוב הדרגתי ומבודד.

## רספונסיביות
מ-1200px: חמש עמודות; 768–1199: שלוש; 360–767: שתיים; מתחת ל-360: אחת. יש לוודא שטח עבודה אמיתי עם Sidebar; אם מעטפת האתר צרה יותר, התאימו לפי רוחב container תוך שמירת יעד 5×2 ב-1366/1440 לאחר בדיקה. Sidebar במובייל משתמש בהתנהגות drawer הקיימת; לא נבנה מחדש בחבילה.

## טקסט והסברים
לכרטיסים הסבר קבוצתי: ״פעילות בתקופה · כולל פעילות מלידים שנכנסו לפני התקופה״. למשפך הסבר נפרד על קבוצת הלידים. אם אין נתון, כותבים זאת; לא מציירים גרף דמה ולא משתמשים ב-0. שומרים על כותרת מדויקת לכל מועד: ״תואמו בתקופה״ שונה מ״יתקיימו בתקופה״.

## מצב החבילה
רכיבי React ו-CSS מוכנים לשילוב, אך אינם מחוברים לשרת או למאגר VITAS. סט הקבצים אינו טוען לשחזור pixel-perfect ואינו מכיל את כל תשעת המסכים בקוד. קודם מאמתים מסך בסיס אמיתי, ואז מרחיבים את השפה לרכיבי CRM וגרפים.
