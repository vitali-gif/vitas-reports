# VITAS — CRM / זמני תגובה

מטרה: לשלב את העיצוב המצורף בתת־הטאב הקיים של HI PARK, בפיילוט נדל״ן. אין לשנות חישובים, הרשאות או מקורות נתונים בשל הסקיצה. החבילה היא בסיס תצוגה; היא טרם שולבה במאגר האמיתי.

## לפני שינוי
1. קרא AGENTS.md והנחיות המאגר; בדוק git status ואל תדרוס עבודה קיימת.
2. קרא app/admin/page.js, את תת־הטאב זמני תגובה, adapters, components/shell ו-globals.css. אתר כל אחד משבעת הניתוחים הקיימים. תעד הגדרת מדד, אוכלוסייה, זמן חתך והחישוב הקיים.
3. צלם מסך ושמור baseline מספרי לתקופה קבועה עבור HI PARK. זהה גם isClientView ומבני KLOSS ו-BCure שיש להשאיר ללא שינוי.
4. שלב בענף עבודה. אין לפרסם לפרודקשן; הצג תצוגה מקדימה והבדלים למשתמש.

## תוכן החבילה
- components/ResponseTimes.jsx — הרכבת המסך; default export.
- components/ResponseChart.jsx — גרף Chart.js אופציונלי עם טבלת נתונים נגישה; default export.
- components/VitasPresentation.jsx + styles/vitas-visual.css — בסיס משותף מהחבילות הקודמות. אם כבר שולב, השתמש בגרסה הקיימת והתאם imports; אין לדרוס אותה.
- styles/response-times.css — עיצוב מקומי עם prefix vrt.
- examples/Example.jsx — דוגמת פיתוח קטנה עם נתונים עקביים ומצבים חסרים. אינה נתוני ייצור או adapter ל-reports.
- reference/response-times-style-only.png — סקיצה חזותית; המספרים והגרפים אינם מקור אמת ואינם עקביים בהכרח ביניהם.
- DATA-CONTRACT.md, ACCEPTANCE.md, VALIDATION.md — כללי חיבור ובדיקה.

## טכנולוגיה ושילוב
React 18, Next.js 14 App Router, Heebo, RTL, lucide-react, CSS classes, Chart.js 4 ישירות על canvas. אין Tailwind, ספריית UI חדשה או react-chartjs-2. רכיבים פונקציונליים ללא inline styles. ה-CSS משתמש במשתני המערכת עם fallback ואינו משנה :root.

המסך נכנס לתוך main הקיים. Sidebar, Header, תאריכים, תקציב, טאבים ותתי־טאבים נשארים רכיבי המעטפת המקוריים. אין להעתיק לוגו מהסקיצה או ליצור מעטפת כפולה. טען CSS פעם אחת: globals.css, אחריו הבסיס המשותף ואחריו response-times.css, בהתאם למוסכמות הפרויקט.

יש להעדיף את הגרפים והחישובים הקיימים ולהעביר את הרכיבים כ-charts slots. אם צריך להחליף renderer בלבד, אפשר להשתמש ב-ResponseChart המצורף. הרוס את מופע Chart הקודם; אל תרנדר שני canvases עבור אותו גרף. אין שינוי Chart.defaults גלובלי. labels ו-datasets חייבים להיות יציבים באמצעות useMemo. בנתונים קטגוריים סדר את labels ואת כל הסדרות יחד; RTL של טקסט אינו סיבה להפוך נתונים באופן חלקי.

## החלטות מחייבות
- זמן מענה: מכניסת הליד עד לשיחה הראשונה שהתקיימה, לפי שעות העבודה הקיימות במערכת. ניסיון חיוג אינו שיחה שהתקיימה.
- חציון מוצע בסקיצה. אם זמני תגובה תקינים לכל ליד זמינים, חשב באותה פונקציית שעות עבודה ואוכלוסייה כמו הממוצע. אין לחשב חציון מממוצעים או ממספרי התרשים. אם אינו זמין, הצג ״אין נתון״ עם הסבר, או שמור את המדד הקיים במקום זה ודווח למשתמש.
- גם ארבעת כרטיסי הסקיצה הם הצעת תצוגה; אין למחוק מדדים קיימים בעלי משמעות כדי להתאים לתמונה. ניתן להוסיף אותם ל-model.metrics.
- טרם התקיימה שיחה אינו זהה ל״לא טופל״, ״לא נענה לניסיון האחרון״ או ״לא רלוונטי״.
- ״שעות ללא מענה״: הסקיצה מציעה ספירת ניסיונות חיוג שלא נענו, אך יש לאמת את הגדרת המערכת. אם המערכת סופרת לידים או שעות המתנה, שמור את החישוב ושנה כותרת/הסבר בהתאם. אל תמציא נתוני ניסיונות חיוג.
- הגרפים יום מבוקש לפגישה ושעות תיאום פגישות הם שונים: יום הפגישה לעומת מועד יצירת התיאום. שמור את ההגדרה הקיימת ותן הסבר ברור לכל אחד.
- אין ספי SLA, יעד, דירוג הצלחה או המלצה לפעולה בלי כלל עסקי קיים. הצבעים הם קטגוריות בלבד.
- סיכומים בטבלאות או גרפים לא בהכרח משתמשים באותה אוכלוסייה; כתוב scope לכל אזור. המוקאפ אינו הנחיה לשנות אוכלוסייה או מקור.

## סדר עבודה
חבר adapter תצוגה נפרד לנתונים הקיימים. ודא null מול 0, מצבי טעינה וחוסר חיבור. לאחר מכן חבר מיון גולמי ורענון לפעולות הקיימות, השווה את כל המספרים ל-baseline והרץ בדיקות/Build לפי המאגר. הצג צילומי דסקטופ ואזורי גלילה ואת רשימת המדדים שאינם זמינים. אל תכניס נתוני Example למערכת אמיתית.
