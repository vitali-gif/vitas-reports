# חוזה תצוגה והגדרות

## API
```jsx
import ResponseTimes from './ResponseTimes';
import ResponseChart from './ResponseChart';
<ResponseTimes model={viewModel} state={pageState} charts={charts}
  onRefresh={refresh} refreshing={refreshing} onRetry={retry}
  repSort={repSort} onRepSort={sortReps}
  sourceSort={sourceSort} onSourceSort={sortSources}
  additionalContent={existingExtraBlocks} />
```
model יכול להיות null רק כאשר state אינו ready. state: ready / loading / empty / missing / error. ברענון לאותה אוכלוסייה אפשר להשאיר תצוגה ולסמן refreshing; בשינוי לקוח/פרויקט/טווח יש להסתיר נתונים קודמים עד התאמת מפתח הבקשה. בטל/התעלם מתשובה ישנה שהגיעה אחרי תשובה חדשה.

model:
- definition: ההגדרה העסקית של זמן המענה; טקסט.
- scope: אוכלוסייה, תקופה וזמן חתך לפי הקיים.
- metrics: מערך {id,label,value,description,tone,icon?,details?}. value מספר/טקסט/null. null מוצג ״אין נתון״; 0 נשאר 0. tone: indigo / sky / emerald / amber / violet / rose / terra.
- panels: distribution, weekday, meetingDay, activityHours, unansweredHours; כל אחד {state,scope,message?}.
- reps, sources: {state,scope,message?,rows,columns?}. rows: [{id,cells:{name,answered,mean,median?,pending}}]. שמות ומזהים מקוריים בלבד. columns אופציונלי מתאים להגדרות המערכת בלי לפגוע במיפוי cells.
- charts: אובייקט עם אותם חמשת המפתחות וערכי ReactNode; גרף מוצג רק כאשר מצבו ready.
- sort: {key,direction:'asc'|'desc'}; ההורה ממיין מספרים גולמיים/זמן בדקות, לא מחרוזות ״שעה״/״דקות״. חסרים ימוקמו באופן עקבי בסוף. callbacks לא מועברים אם אין פעולה זמינה.

## כללים ל-adapter
שמרו את מחשבון שעות העבודה הקיים, אזור הזמן, ימי העבודה/החרגות וחגים אם נתמכים. אין ליצור לוח שעות חדש מהנחות. אל תשנו דרך טיפול בלידים מחוץ לשעות עבודה ללא אישור עסקי. תעדו את ההתנהגות הקיימת.

זמן שלילי, תאריך חסר או לא תקין אינו אפס. ליד ללא שיחה אינו נכלל בממוצע או בחציון. ליד עם שיחה אבל חותמות זמן חסרות יכול להיכלל בספירת השיחות אך לא במדדי הזמן; הציגו את גודל המדגם התקין ליד הזמן. אין להסיק ״ממתינים״ אוטומטית מהפרש ספירות אם האוכלוסיות שונות.

חציון: מיון זמני התגובה התקינים; בערך זוגי ממוצע שני האמצעיים. ממוצע כולל: סכום הזמנים חלקי מספר התצפיות התקינות, לא ממוצע ממוצעי הנציגים. חציון כולל לא נגזר מחציוני הנציגים.

לכל גרף יש לציין יחידה וסוג תאריך: כניסת ליד / מועד שיחה / מועד יצירת תיאום / מועד הפגישה. טווחי התפלגות צריכים להיות לא חופפים. הדוגמה בלבד משתמשת ב-[0,5), [5,15), [15,30), [30,60), [60,∞); שמרו טווחים קיימים בייצור אם שונים. אל תטענו שאלו ספי הצלחה.

טבלת מקור איטי: שמרו את מדד המיון הקיים; הציגו גודל מדגם ליד כל מקור כדי שלא לתת משקל מוגזם למקור עם ליד אחד. אין להמציא סף למדגם קטן. שייכות נציג/מקור ושיחות מרובות נקבעות לפי הכללים הקיימים; אין לספור ליד פעמיים ללא הגדרה מפורשת.

## ResponseChart האופציונלי
props: label, labels:string[], datasets:[{id,label,values:(number|null)[],colorKey?}], unit, type ('bar'/'line'), horizontal:boolean. כל הסדרות באותו אורך כמו labels. מספרים לא שליליים וסופיים. null נשאר חסר; מערך אפסים הוא נתון תקין. גרף נכשל משאיר טבלת נתונים זמינה. הרכיב אינו מבצע עסקית aggregation, חישוב זמני עבודה או מיון. התאימו tooltip ופורמט יחידות למערכת בעת השילוב.

## פריסה
4 כרטיסים בשורה רחבה; שני גרפים בשורת מהירות המענה ושלושה בשורת דפוסי פעילות כאשר הרוחב מאפשר. מתחת 1200px דפוסים עוברים ל-2 עמודות; מתחת 850px גרפים נערמים. רווח 24px בין פאנלים ו-32px בין אזורים. טבלאות גוללות מקומית ברוחב חסר. אין לכווץ את כל הדוח למסך אחד. מובייל שומר נתונים וגלילה נגישה, גם כשהפיילוט מיועד לדסקטופ.
